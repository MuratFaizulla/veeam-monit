# Veeam Telegram Monitor

Telegram-бот для наблюдения за **Veeam Backup & Replication** через REST API. Сервис на NestJS проверяет доступность Veeam, работу служебной учётной записи, результаты заданий и свободное место в репозиториях. При изменениях он отправляет оповещения в Telegram. По запросу показывает сводку и карточку задания.

В группах с включёнными темами бот также поддерживает сообщения с текущим состоянием: редактирует их на месте и периодически обновляет время последней проверки. Веб-панели в этом проекте нет.

## Возможности

- Оповещения о новых ошибках и предупреждениях заданий, восстановлении, потере и возвращении связи с Veeam, проблемах авторизации и нехватке места в репозитории.
- Живые темы: состояние монитора, выполняющиеся и запланированные задания, производительность, репозитории, защита и точки восстановления. Тема с резервными копиями без действующего задания отключена по умолчанию.
- Команды в Telegram для проверки состояния, запуска цикла опроса, просмотра сводки и отдельного задания. Под ответами есть кнопки для перехода к заданиям и обновления данных.
- Меню под полем ввода, как у корпоративных ботов: «🖥 Серверы», «📊 Сводка», «🔄 Проверить», «🩺 Статус», «🤖 Помощь».
- Несколько серверов Veeam в одном боте: оповещения приходят со всех, а живые темы, `/digest` и `/job` показывают сервер, выбранный в меню «🖥 Серверы».
- Маршрутизация оповещений по темам, фильтрация по важности и дополнительные правила из JSON-файла.
- HTTP API для проверки состояния, ручного запуска цикла, тестовой отправки и управления правилами маршрутизации.

Опрос Veeam запускается при старте и затем по таймеру. Повторяющиеся оповещения ограничиваются периодами ожидания. Результаты заданий, запуски, которые Veeam ещё повторяет, известные чаты и темы, идентификаторы живых сообщений и периоды ожидания хранятся в `data/telegram-state.json`.

После каждой записи сервис сохраняет рядом копию `data/telegram-state.json.bak`. Если основной файл повреждён, при следующем запуске состояние восстанавливается из копии. Для защиты от потери всего диска копируйте оба файла на другой носитель. Неверные адреса, интервалы и другие числовые настройки из `.env` теперь останавливают запуск с указанием имени переменной.

## Требования

- Node.js 22+ и npm **или** Docker с Compose.
- Доступ к REST API Veeam Backup & Replication, обычно на порту `9419`.
- Отдельная учётная запись Veeam для чтения данных; рекомендуемая роль — **Veeam Backup Viewer**.
- Telegram-бот, созданный через BotFather, и чат, в который он добавлен.

Для отдельных тем нужна супергруппа с включённым режимом форума. Чтобы бот создавал темы сам, выдайте ему право **Manage topics**. Если права нет, сообщения, для которых тема недоступна, попадут в General. В обычном чате все сообщения также идут без разделения по темам.

## Быстрый запуск

1. Скопируйте `.env.example` в `.env` и заполните как минимум:

   ```dotenv
   VEEAM_SERVERS=https://veeam.example:9419
   VEEAM_MONITOR_USERNAME=service-account
   VEEAM_MONITOR_PASSWORD=your-password
   TELEGRAM_BOT_TOKEN=your-bot-token
   TELEGRAM_CHAT_IDS=-1001234567890
   TELEGRAM_ADMIN_KEY=  # не короче 32 символов: openssl rand -hex 32
   ```

   `TELEGRAM_CHAT_IDS` принимает несколько ID через запятую. Это единственные чаты, куда бот отправляет оповещения и живые сообщения; как он обходится со всеми остальными — в разделе «Кто может говорить с ботом». Чтобы узнать ID новой группы, запустите бот с пустым `TELEGRAM_CHAT_IDS` и наберите в группе `/chatid`. Настоящие токены и пароли не добавляйте в репозиторий.

2. Запустите сервис локально:

   ```bash
   npm ci
   npm run start:dev
   ```

   Для запуска собранной версии: `npm run build`, затем `npm run start:prod`.

   **Или** запустите через Docker Compose:

   ```bash
   docker compose up -d --build
   docker compose logs -f
   ```

3. Проверьте `GET http://localhost:3000/api/telegram/status` с заголовком `X-Telegram-Admin-Key`. Поле `mode` должно стать `polling` или `webhook`, а `monitor.lastCheckAt` — заполниться после первого цикла. `GET /api/health` показывает доступность Veeam в поле `veeam.reachable`; сам маршрут отвечает HTTP 200 и при недоступном Veeam.

Compose публикует порт `HOST_PORT` (по умолчанию `3000`) только на `HOST_BIND` (по умолчанию `127.0.0.1`), сохраняет `./data` и `./logs` на хосте, отдаёт контейнеру `./certs` только для чтения (сертификаты для `VEEAM_TLS_CERTS`) и держит журнал Docker в пределах трёх файлов по 10 МБ. Контейнер работает без привилегий: процесс запущен не от root, без Linux capabilities и без возможности их получить, файловая система доступна только для чтения (кроме `./data`, `./logs` и `/tmp`), память ограничена 512 МБ. Для доступа через сеть явно задайте `HOST_BIND=0.0.0.0` и ограничьте порт firewall или reverse proxy. Сохраняйте `./data` между перезапусками: иначе бот потеряет привязку к уже опубликованным живым сообщениям и историю оповещений. Если Veeam работает на том же хосте, что и Docker, используйте в адресе сервера имя `host.docker.internal` вместо `localhost`.

### Запуск через PM2

PM2 запускает собранный Node.js-сервис по [ecosystem.config.cjs](ecosystem.config.cjs). Выполняйте команды из корня проекта; `.env` будет загружен приложением из этого каталога. Держите запущенным только один экземпляр бота: параллельный запуск через Docker и PM2 приведёт к двум циклам мониторинга и конфликту long polling.

На Windows перед командами PM2 установите его рабочую папку для текущего терминала PowerShell. Используйте тот же `PM2_HOME` при просмотре состояния, перезапуске и остановке:

```powershell
$env:PM2_HOME = Join-Path (Get-Location) '.pm2'
```

```bash
npm ci
npm run build
pm2 start ecosystem.config.cjs
pm2 status
pm2 logs veeam-telegram-monitor
```

После обновления кода выполните `npm run build` и `pm2 restart veeam-telegram-monitor --update-env`. Для остановки используйте `pm2 stop veeam-telegram-monitor`. На Windows автоматический запуск после перезагрузки нужно настроить отдельно средствами системы.

## Подключение Telegram

По умолчанию бот использует **long polling**: публичный адрес не нужен. Если задан `TELEGRAM_WEBHOOK_URL`, сервис регистрирует webhook по адресу `<TELEGRAM_WEBHOOK_URL>/api/telegram/webhook`. Укажите публичный HTTPS-адрес, доступный Telegram, и задайте `TELEGRAM_WEBHOOK_SECRET`: входящий запрос проверяется по заголовку `X-Telegram-Bot-Api-Secret-Token`. При использовании webhook настройте также HTTPS и переадресацию на HTTP-порт сервиса.

По умолчанию `TELEGRAM_ROUTING_MODE=single`:

| Событие | Куда отправляется в форуме |
| --- | --- |
| Ошибка или предупреждение | `🚨 Alerts` |
| Восстановление | `🟢 Recovered` |
| Информационное событие | General |

Живые сообщения размещаются в собственных темах независимо от режима маршрутизации. Другие режимы: `severity` — тема по важности, `kind` — по категории, `job` — отдельная тема для каждого задания. При `TELEGRAM_CREATE_TOPICS=false` бот использует известные темы и отправляет остальные сообщения в General. Названия тем и все параметры приведены в [.env.example](.env.example).

Для адресных правил скопируйте [telegram-routes.example.json](telegram-routes.example.json), укажите путь в `TELEGRAM_ROUTES_FILE` и перечитайте файл через `POST /api/telegram/routes/reload`. Правила проверяются сверху вниз; применяется первое совпадение.

### Повторы Veeam

Veeam повторяет упавшее задание новой сессией, поэтому одна плохая ночь выглядит как три-четыре отказа. Пока идёт повтор, задание сообщает результат `none`, и сервис **не** записывает его поверх известного: `none` — это «сейчас не знаю», а не результат. Без этого один сломанный запуск давал сообщение на каждую попытку, а восстановление не приходило никогда — потому что восстановление определено как «предыдущий результат был плохим», а к моменту успеха предыдущим значился `none`.

В оповещении есть строка **«Попытка: 2 из 4»**. Номер считается по сессиям: две сессии — один запуск, если новая началась в пределах окна повтора после окончания предыдущей (`awaitMinutes` задания плюс запас на длительность самой попытки). В той же строке сказано, что будет дальше: «Veeam повторит ≈ сегодня в 04:33», пока попытки остались, «повтор уже идёт», если следующая попытка уже запущена, или «повторов больше не будет». Veeam повторяет только те запуски, которые начал сам, поэтому для заданий, запускаемых только вручную или выключенных в Veeam, бот повтор не обещает и не ждёт.

Об отказе бот сообщает после первой попытки и дальше следит за запуском. Промежуточные неудачные повторы молчат. Если повтор удался, приходит «задание восстановлено» с номером попытки. Если Veeam перестал повторять — все попытки кончились или пауза прошла без новой, — приходит одно сообщение «ОШИБКА, повторов больше не будет». Пока следующая попытка не началась, слежение не делает запросов к Veeam. Запуск, за которым идёт слежение, хранится в `data/telegram-state.json`, поэтому перезапуск бота между попытками последнее сообщение не теряет.

Под оповещением об отказе или предупреждении перечислены ВМ, которые не прошли, с причиной от Veeam: например, `🔴 EMMDB1-T3Q4 — Failed to open VDDK disk […] ( is read-only mode - [true] )`. На REST API 1.2 причина берётся из задач сессии, на 1.1 — из лога сессии. Показываются до пяти ВМ каждого вида, остальные считаются. Если Veeam ни одну ВМ не назвал (например, «Virtual Machine … is unavailable»), выводится сообщение самой сессии.

### Живые сообщения и лимит Telegram

Telegram разрешает боту править и удалять собственное сообщение примерно двое суток **с момента отправки** — сколько бы раз его ни редактировали после. Поэтому живое сообщение темы заменяется новым через 36 часов, пока старое ещё можно удалить. Если этого не делать, однажды правка не проходит, удаление тоже не проходит, и в теме остаются два сообщения: одно навсегда застывшее на старых данных, второе актуальное. Сообщение с неизвестной датой отправки (сохранённое старой версией) заменяется сразу.

Если такие «застывшие» сообщения уже есть в чате, бот их удалить не может — они старше двух суток. Их нужно удалить вручную.

Если в группе включено **автоудаление** Telegram, держите его **больше 36 часов**, иначе живое сообщение исчезнет раньше, чем сервис успеет заменить его сам. Даже в этом случае потери нет: слот заметит пропажу при ближайшей перезаписи (не позже чем через `TELEGRAM_LIVE_REFRESH_MIN` минут) и опубликует новое. Но лишняя пересылка будет. Автоудаление распространяется на всю группу, включая все темы, и применяется только к сообщениям, отправленным после его включения — задним числом оно ничего не удаляет.

Помните и о цене: автоудаление одинаково стирает и живые сообщения, и **оповещения**. Тема 🚨 Alerts превращается в скользящее окно, и через заданный срок от истории отказов не остаётся ничего.

### Если тему удалили

Удалённую тему бот создаёт заново под тем же именем и сразу кладёт в неё текущее живое сообщение. Если содержимое темы меняется, она вернётся в следующем цикле проверки. Если не меняется — не позже чем через `TELEGRAM_LIVE_REFRESH_MIN` минут (по умолчанию 5). Тема 🚨 Alerts вернётся со следующим оповещением. Сообщения удалённой темы Telegram стирает вместе с ней, поэтому прежняя история оповещений из неё не восстанавливается.

Разовый сбой Telegram — 429, 5xx, оборванное соединение — не повод публиковать новое сообщение. Живое сообщение остаётся на месте, в следующем цикле бот правит его снова, а причину сбоя пишет в журнал: `was not refreshed, kept for the next cycle`.

## Команды бота

| Команда | Результат |
| --- | --- |
| `/status` | Доступность Veeam, авторизация, количество заданий и время последней проверки. `/chatid` показывает тот же ответ вместе с ID чата. |
| `/menu` | Показывает меню под полем ввода, если оно пропало. `/start` — то же самое: это нажатие «Start» в личном чате с ботом. |
| `/servers` | Серверы Veeam и их состояние; меню под полем ввода превращается в кнопки серверов. Кнопкой выбирается сервер, который показывают живые темы, `/digest` и `/job`. |
| `/check` | Немедленно запускает цикл опроса, если другой цикл не выполняется; повторный ручной вызов ограничен 30 секундами. |
| `/digest` | Текущая сводка по заданиям и список проблемных. Задания, выключенные в Veeam, в список проблемных не попадают, даже если их последний запуск был с ошибкой: они считаются отдельной строкой «Выключены в Veeam». |
| `/job часть имени` | Карточка задания с последним результатом, запусками, расписанием и точками восстановления. Поиск допускает часть имени без учёта регистра. |
| `/topics` | Список тем, известных боту в этом чате. |
| `/clear` | Очищает General: удаляет всё, что там было сказано за последние 48 часов, — команды и нажатия кнопок, обычные сообщения, ответы бота, меню и события. Последним остаётся свежее меню. Темы с оповещениями и живыми сообщениями не трогает. Подробности — в разделе «Меню под полем ввода». |
| `/help` | Справка по командам. |

### Кто может говорить с ботом

Бот публичный: его можно найти по имени, написать ему или добавить в свою группу. Поэтому:

| Кто | Что получает |
| --- | --- |
| Группа из `TELEGRAM_CHAT_IDS` | Всё: оповещения, живые темы, команды и меню. |
| Личный чат участника такой группы | Меню и команды, как у других корпоративных ботов. Оповещения и живые сообщения туда не приходят. Членство бот проверяет у Telegram и помнит ответ 10 минут: вышедший из группы теряет доступ в течение 10 минут. |
| Любая другая группа | Ничего. Бот сам выходит из неё и пишет об этом в журнал. |
| Любой другой личный чат | Ничего, даже отказа. |

Пока `TELEGRAM_CHAT_IDS` пуст, бот в любом чате отвечает только на `/chatid`, `/start` и `/status` — и только ID этого чата, без данных Veeam. Чаты, которые прежние версии запомнили сами, при запуске забываются вместе с их темами и живыми сообщениями.

### Меню под полем ввода

Бот держит в General сообщение «Меню Veeam Monitor» с клавиатурой под полем ввода. Клавиатура живёт, пока существует это сообщение, поэтому бот запоминает его и каждые `TELEGRAM_LIVE_REFRESH_MIN` минут (по умолчанию 5) проверяет, на месте ли оно. Если сообщение удалили, бот публикует меню заново. Перезапуск и разовый сбой Telegram нового меню не создают. Кнопки главного меню:

| Кнопка | Что делает |
| --- | --- |
| 🖥 Серверы | Список серверов и их состояние; клавиатура сменяется кнопками серверов и «⬅️ На главную». Нажатие на сервер делает его выбранным и возвращает главное меню. |
| 📊 Сводка | То же, что `/digest`. |
| 🔄 Проверить | То же, что `/check`. |
| 🩺 Статус | То же, что `/status`. |
| 🤖 Помощь | То же, что `/help`. |

Меню серверов и возврат на главную меняют клавиатуру только тому, кто нажал, — у остальных в группе остаётся главное меню. `/menu` показывает меню сразу, не дожидаясь проверки. Нажатая кнопка приходит в чат обычным сообщением: бот видит его, потому что он администратор группы (иначе нужно выключить privacy mode в BotFather).

`/clear` очищает General полностью, насколько позволяет Telegram:

- Бот удаляет всё, что видел в General: команды и нажатия кнопок, обычные сообщения людей, свои ответы, меню и события. Последним сообщением он публикует свежее меню с итогом, так что клавиатура не пропадает.
- Удалить можно только сообщения моложе 48 часов. Кроме того, бот знает лишь то, что увидел сам, начиная с версии, где General записывается целиком. Более старое удаляйте вручную.
- Чужие сообщения бот удаляет, только если у него, как у администратора, есть право «Удаление сообщений». Если права нет, в итоге будет написано, сколько сообщений «не поддались».
- Темы с оповещениями и живыми сообщениями `/clear` не трогает: это записи о событиях.

В группе-форуме команды и кнопки бота работают только в теме **General**. В остальных темах бот их игнорирует; оповещения и живые сообщения продолжают приходить в свои темы. В обычном чате без форума команды доступны как прежде. `/digest` и `/job` читают данные Veeam при запросе и ограничены коротким интервалом между чтениями.

## Несколько серверов Veeam

Серверы перечисляются в `VEEAM_SERVERS`; у всех одна служебная учётная запись. Версии Veeam могут различаться: версию REST API бот подбирает для каждого сервера сам.

- **Оповещения** приходят со всех серверов в те же темы. Когда серверов больше одного, заголовок начинается с имени сервера: `BAAS · Files: ОШИБКА`. Ежедневная сводка приходит по каждому серверу отдельно.
- **Живые темы, `/digest` и `/job`** показывают один сервер — выбранный. Первым выбран первый в списке; сменить можно кнопкой «🖥 Серверы» в меню или командой `/servers`. Выбор общий для группы и переживает перезапуск. Над каждым живым сообщением стоит имя показанного сервера, а в теме 🩺 перечислены все серверы, их состояние и IP-адреса — те, в которые бот резолвит их имена при подключении.
- **Нагрузка.** Каждый цикл спрашивает у каждого сервера доступность, статусы заданий и заполненность репозиториев. Полное сканирование точек восстановления и выполняющиеся сессии читаются только у выбранного сервера; после переключения первое обновление живых тем может занять до минуты, пока идёт сканирование.
- **Новый сервер** в списке первый цикл только запоминает: уже упавшие на нём задания не присылаются оповещением. То же после переименования сервера — бот узнаёт его заново.

Файл состояния от версии с одним сервером читается как состояние первого сервера в списке, поэтому при переходе ничего не теряется.

## Основные настройки

Полный перечень с комментариями и значениями по умолчанию — в [.env.example](.env.example).

| Переменная | Назначение |
| --- | --- |
| `VEEAM_SERVERS` | Серверы Veeam через запятую: `имя=адрес` или просто адрес (тогда имя — первая часть имени хоста). |
| `VEEAM_BASE_URL` | Прежний способ указать один сервер. Задаётся либо он, либо `VEEAM_SERVERS`. |
| `VEEAM_LEGACY_TLS` | Имена серверов, которым в TLS-рукопожатии предлагаются старые алгоритмы (подписи SHA-1). Нужно старому серверу, который иначе обрывает соединение с `ECONNRESET`. Ослабляет TLS только для названных серверов. |
| `VEEAM_API_VERSION` | Версия заголовка API. Сервер на более старой сборке Veeam отказывает и называет свои версии; с ним бот говорит на новейшей из них и один раз пишет об этом в журнал. |
| `VEEAM_MONITOR_USERNAME`, `VEEAM_MONITOR_PASSWORD` | Данные служебной учётной записи, одной на все серверы. |
| `VEEAM_TLS_CERTS` | Закрепление сертификатов: `имя=путь` через запятую, где путь ведёт к PEM-сертификату, который отдаёт этот сервер. У Veeam по умолчанию самоподписанный сертификат «Veeam Backup Server Certificate» без имени сервера, поэтому ни один центр сертификации за него не поручится. Закреплённому серверу бот доверяет ровно этому сертификату, проверяя отпечаток SHA-256 в TLS-рукопожатии, до отправки пароля. В Docker папка `./certs` видна как `/app/certs`. Если Veeam сменит сертификат, сервер будет недоступен с ошибкой `CERT_NOT_PINNED`; тогда положите новый файл. |
| `VEEAM_INSECURE_TLS` | Отключить проверку сертификата для всех незакреплённых серверов; небезопасно, по умолчанию `false`. |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_IDS` | Токен бота и чаты, куда он отправляет оповещения и живые сообщения. Другие чаты получателями не становятся. |
| `TELEGRAM_WEBHOOK_URL`, `TELEGRAM_WEBHOOK_SECRET` | Публичный адрес и секрет webhook; пустой URL включает long polling. Секрет — не короче 32 символов. |
| `TELEGRAM_ADMIN_KEY` | Ключ для операторских HTTP-маршрутов, не короче 32 символов (`openssl rand -hex 32`). Пустой закрывает эти маршруты для всех; более короткий бот не примет при запуске. |
| `TELEGRAM_MONITOR_INTERVAL_MS` | Интервал проверки Veeam; по умолчанию 60 секунд, `0` отключает периодический опрос. |
| `TELEGRAM_ROUTING_MODE`, `TELEGRAM_ROUTES_FILE` | Режим маршрутизации и необязательный файл правил. |
| `TELEGRAM_LIVE`, `TELEGRAM_LIVE_ORPHANS` | Живые темы и отдельная тема резервных копий без задания. |
| `TELEGRAM_PROTECTION_INTERVAL_MIN` | Интервал полного сканирования точек восстановления; по умолчанию 60 минут (1 час). Первый сбор запускается при старте сервиса, а при переключении на другой сервер он сканируется сразу, если его данным больше 10 минут. |
| `TELEGRAM_TIMEZONE` | Часовой пояс IANA для времени в сообщениях; пустое значение берёт пояс сервера. |
| `TELEGRAM_DIGEST_HOUR` | Час ежедневной сводки; `-1` отключает её. Команда `/digest` доступна независимо от этого параметра. |
| `TELEGRAM_STATE_FILE`, `LOG_FILE` | Пути к файлу состояния и журналу. |

## HTTP API и диагностика

| Маршрут | Доступ | Назначение |
| --- | --- | --- |
| `GET /api/health` | Открытый | Проверка доступности серверов Veeam без раскрытия их имён, адресов и сетевых ошибок. |
| `GET /api/telegram/status` | `X-Telegram-Admin-Key` | Состояние интеграции, очереди и монитора. |
| `POST /api/telegram/webhook` | Секрет webhook | Входящие обновления Telegram. |
| `GET /api/telegram/chats` | Ключ администратора | Известные чаты и темы. |
| `GET /api/telegram/routes` | Ключ администратора | Действующие правила и настройки маршрутизации. |
| `POST /api/telegram/routes/reload` | Ключ администратора | Повторно прочитать файл правил. |
| `POST /api/telegram/check` | Ключ администратора | Запустить один цикл проверки. |
| `POST /api/telegram/test` | Ключ администратора | Отправить тестовое событие через маршрутизатор. |
| `POST /api/telegram/notify` | Ключ администратора | Отправить произвольное объявление. |

В операторских запросах передавайте ключ в заголовке `X-Telegram-Admin-Key`. Интерактивное описание схем запросов доступно по `/api/docs`, JSON — по `/api/docs-json`; по умолчанию они отключены и включаются через `API_DOCS=true`. Если оповещения не приходят, проверьте `GET /api/telegram/status`, лог в `logs/backend.log` и количество обнаруженных чатов. Для проверки всего пути доставки используйте `POST /api/telegram/test` с телом, описанным в `/api/docs`.

### Модули и папки

Один Nest-модуль на предмет и одна папка на модуль. Папки лежат слоями, и
любой импорт — и между Nest-модулями, и между файлами — идёт только вниз:

```
updates   TelegramUpdatesModule   команды, кнопки, webhook, HTTP-эндпоинты
monitor   MonitorModule           цикл опроса и алерты; наружу отдаёт только MONITOR
live      LiveModule              live-слоты: что в них написано и одно сообщение на слот
estate    EstateModule            Evidence, карточка задания, сводка, Run'ы
veeam     VeeamModule             HTTP-клиент, токен, модуль чтения, имена репозиториев и прокси
telegram  TelegramModule          доставка: чаты, темы, маршрутизация, файл состояния, язык бота
config                            настройки: одно объявление на переменную
```

Две папки без своего модуля тоже стоят в слоях: `logging` (файловый логгер) — внизу, рядом с `config`; `http` (проба `/api/health` и описание API) — наверху, рядом с `updates`.

`veeam` и `telegram` — соседи одного слоя и друг друга не импортируют. Файл,
который сам ничего из проекта не импортирует (имена слотов, виды уведомлений),
может использовать любой слой.

`test/architecture.test.cjs` падает, если импорт укажет вверх или вбок — между
Nest-модулями или между файлами разных папок, — или если приложение перестанет
собираться.

Файл [docs/veeam-openapi.json](docs/veeam-openapi.json) описывает API самого Veeam; `/api/docs` описывает API этого сервиса.
