# Veeam Telegram Monitor

Telegram-бот для наблюдения за **Veeam Backup & Replication** через REST API. Сервис на NestJS проверяет доступность Veeam, работу служебной учётной записи, результаты заданий и свободное место в репозиториях. При изменениях он отправляет оповещения в Telegram. По запросу показывает сводку и карточку задания.

В группах с включёнными темами бот также поддерживает сообщения с текущим состоянием: редактирует их на месте и периодически обновляет время последней проверки. Веб-панели в этом проекте нет.

## Возможности

- Оповещения о новых ошибках и предупреждениях заданий, восстановлении, потере и возвращении связи с Veeam, проблемах авторизации и нехватке места в репозитории.
- Живые темы: состояние монитора, выполняющиеся и запланированные задания, производительность, репозитории, защита и точки восстановления. Тема с резервными копиями без действующего задания отключена по умолчанию.
- Команды в Telegram для проверки состояния, запуска цикла опроса, просмотра сводки и отдельного задания. Под ответами есть кнопки для перехода к заданиям и обновления данных.
- Несколько серверов Veeam в одном боте: оповещения приходят со всех, а живые темы, `/digest` и `/job` показывают сервер, выбранный в меню `/servers`.
- Маршрутизация оповещений по темам, фильтрация по важности и дополнительные правила из JSON-файла.
- HTTP API для проверки состояния, ручного запуска цикла, тестовой отправки и управления правилами маршрутизации.

Опрос Veeam запускается при старте и затем по таймеру. Повторяющиеся оповещения ограничиваются периодами ожидания. Результаты заданий, известные чаты и темы, идентификаторы живых сообщений и периоды ожидания хранятся в `data/telegram-state.json`.

После каждой записи сервис сохраняет рядом копию `data/telegram-state.json.bak`. Если основной файл повреждён, при следующем запуске состояние восстанавливается из копии. Для защиты от потери всего диска копируйте оба файла на другой носитель. Неверные адреса, интервалы и другие числовые настройки из `.env` теперь останавливают запуск с указанием имени переменной.

## Требования

- Node.js 20+ и npm **или** Docker с Compose.
- Доступ к REST API Veeam Backup & Replication, обычно на порту `9419`.
- Отдельная учётная запись Veeam для чтения данных; рекомендуемая роль — **Veeam Backup Viewer**.
- Telegram-бот, созданный через BotFather, и чат, в который он добавлен.

Для отдельных тем нужна супергруппа с включённым режимом форума. Чтобы бот создавал темы сам, выдайте ему право **Manage topics**. Если права нет, сообщения, для которых тема недоступна, попадут в General. В обычном чате все сообщения также идут без разделения по темам.

## Быстрый запуск

1. Скопируйте `.env.example` в `.env` и заполните как минимум:

   ```dotenv
   VEEAM_SERVERS=https://veeam.example:9419
   VEEAM_MONITOR_USERNAME=service-account
   VEEAM_MONITOR_PASSWORD=your-password
   TELEGRAM_BOT_TOKEN=your-bot-token
   TELEGRAM_CHAT_IDS=-1001234567890
   TELEGRAM_ADMIN_KEY=long-random-secret
   ```

   `TELEGRAM_CHAT_IDS` принимает несколько ID через запятую. Указанный чат доступен для отправки сразу после запуска. Бот также запоминает чаты, от которых получает обновления. Настоящие токены и пароли не добавляйте в репозиторий.

2. Запустите сервис локально:

   ```bash
   npm ci
   npm run start:dev
   ```

   Для запуска собранной версии: `npm run build`, затем `npm run start:prod`.

   **Или** запустите через Docker Compose:

   ```bash
   docker compose up -d --build
   docker compose logs -f
   ```

3. Проверьте `GET http://localhost:3000/api/telegram/status`. Поле `mode` должно стать `polling` или `webhook`, а `monitor.lastCheckAt` — заполниться после первого цикла. `GET /api/health` показывает доступность Veeam в поле `veeam.reachable`; сам маршрут отвечает HTTP 200 и при недоступном Veeam.

Compose публикует порт `HOST_PORT` (по умолчанию `3000`) и сохраняет `./data` и `./logs` на хосте. Сохраняйте `./data` между перезапусками: иначе бот потеряет привязку к уже опубликованным живым сообщениям и историю оповещений. Если Veeam работает на том же хосте, что и Docker, используйте в адресе сервера имя `host.docker.internal` вместо `localhost`.

### Запуск через PM2

PM2 запускает собранный Node.js-сервис по [ecosystem.config.cjs](ecosystem.config.cjs). Выполняйте команды из корня проекта; `.env` будет загружен приложением из этого каталога. Держите запущенным только один экземпляр бота: параллельный запуск через Docker и PM2 приведёт к двум циклам мониторинга и конфликту long polling.

На Windows перед командами PM2 установите его рабочую папку для текущего терминала PowerShell. Используйте тот же `PM2_HOME` при просмотре состояния, перезапуске и остановке:

```powershell
$env:PM2_HOME = Join-Path (Get-Location) '.pm2'
```

```bash
npm ci
npm run build
pm2 start ecosystem.config.cjs
pm2 status
pm2 logs veeam-telegram-monitor
```

После обновления кода выполните `npm run build` и `pm2 restart veeam-telegram-monitor --update-env`. Для остановки используйте `pm2 stop veeam-telegram-monitor`. На Windows автоматический запуск после перезагрузки нужно настроить отдельно средствами системы.

## Подключение Telegram

По умолчанию бот использует **long polling**: публичный адрес не нужен. Если задан `TELEGRAM_WEBHOOK_URL`, сервис регистрирует webhook по адресу `<TELEGRAM_WEBHOOK_URL>/api/telegram/webhook`. Укажите публичный HTTPS-адрес, доступный Telegram, и задайте `TELEGRAM_WEBHOOK_SECRET`: входящий запрос проверяется по заголовку `X-Telegram-Bot-Api-Secret-Token`. При использовании webhook настройте также HTTPS и переадресацию на HTTP-порт сервиса.

По умолчанию `TELEGRAM_ROUTING_MODE=single`:

| Событие | Куда отправляется в форуме |
| --- | --- |
| Ошибка или предупреждение | `🚨 Alerts` |
| Восстановление | `🟢 Recovered` |
| Информационное событие | General |

Живые сообщения размещаются в собственных темах независимо от режима маршрутизации. Другие режимы: `severity` — тема по важности, `kind` — по категории, `job` — отдельная тема для каждого задания. При `TELEGRAM_CREATE_TOPICS=false` бот использует известные темы и отправляет остальные сообщения в General. Названия тем и все параметры приведены в [.env.example](.env.example).

Для адресных правил скопируйте [telegram-routes.example.json](telegram-routes.example.json), укажите путь в `TELEGRAM_ROUTES_FILE` и перечитайте файл через `POST /api/telegram/routes/reload`. Правила проверяются сверху вниз; применяется первое совпадение.

### Повторы Veeam

Veeam повторяет упавшее задание новой сессией, поэтому одна плохая ночь выглядит как три-четыре отказа. Пока идёт повтор, задание сообщает результат `none`, и сервис **не** записывает его поверх известного: `none` — это «сейчас не знаю», а не результат. Без этого один сломанный запуск давал сообщение на каждую попытку, а восстановление не приходило никогда — потому что восстановление определено как «предыдущий результат был плохим», а к моменту успеха предыдущим значился `none`.

В оповещении есть строка **«Попытка: 2 из 4»**. Номер считается по сессиям: две сессии — один запуск, если новая началась в пределах окна повтора после окончания предыдущей (`awaitMinutes` задания плюс запас на длительность самой попытки).

### Живые сообщения и лимит Telegram

Telegram разрешает боту править и удалять собственное сообщение примерно двое суток **с момента отправки** — сколько бы раз его ни редактировали после. Поэтому живое сообщение темы заменяется новым через 36 часов, пока старое ещё можно удалить. Если этого не делать, однажды правка не проходит, удаление тоже не проходит, и в теме остаются два сообщения: одно навсегда застывшее на старых данных, второе актуальное. Сообщение с неизвестной датой отправки (сохранённое старой версией) заменяется сразу.

Если такие «застывшие» сообщения уже есть в чате, бот их удалить не может — они старше двух суток. Их нужно удалить вручную.

Если в группе включено **автоудаление** Telegram, держите его **больше 36 часов**, иначе живое сообщение исчезнет раньше, чем сервис успеет заменить его сам. Даже в этом случае потери нет: слот с сердцебиением заметит пропажу на ближайшем цикле, а закреплённый — на ближайшей проверке существования, и опубликует новое. Но лишняя пересылка будет. Автоудаление распространяется на всю группу, включая все темы, и применяется только к сообщениям, отправленным после его включения — задним числом оно ничего не удаляет.

Помните и о цене: автоудаление одинаково стирает и живые сообщения, и **оповещения**. Тема 🚨 Alerts превращается в скользящее окно, и через заданный срок от истории отказов не остаётся ничего.

## Команды бота

| Команда | Результат |
| --- | --- |
| `/status` | Доступность Veeam, авторизация, количество заданий и время последней проверки. `/start` и `/chatid` показывают тот же ответ вместе с ID чата. |
| `/servers` | Серверы Veeam и их состояние. Кнопкой выбирается сервер, который показывают живые темы, `/digest` и `/job`; меню перерисовывается на месте. |
| `/check` | Немедленно запускает цикл опроса, если другой цикл не выполняется; повторный ручной вызов ограничен 30 секундами. |
| `/digest` | Текущая сводка по заданиям и список проблемных. |
| `/job часть имени` | Карточка задания с последним результатом, запусками, расписанием и точками восстановления. Поиск допускает часть имени без учёта регистра. |
| `/topics` | Список тем, известных боту в этом чате. |
| `/clear` | Удаляет ответы бота в General за последние 48 часов, если Telegram позволяет. Оповещения и живые сообщения остаются. |
| `/help` | Справка по командам. |

В группе-форуме команды и кнопки бота работают только в теме **General**. В остальных темах бот их игнорирует; оповещения и живые сообщения продолжают приходить в свои темы. В обычном чате без форума команды доступны как прежде. `/digest` и `/job` читают данные Veeam при запросе и ограничены коротким интервалом между чтениями.

## Несколько серверов Veeam

Серверы перечисляются в `VEEAM_SERVERS`; у всех одна служебная учётная запись. Версии Veeam могут различаться: версию REST API бот подбирает для каждого сервера сам.

- **Оповещения** приходят со всех серверов в те же темы. Когда серверов больше одного, заголовок начинается с имени сервера: `BAAS · Files: ОШИБКА`. Ежедневная сводка приходит по каждому серверу отдельно.
- **Живые темы, `/digest` и `/job`** показывают один сервер — выбранный. Первым выбран первый в списке; сменить можно командой `/servers` или кнопкой «🖥 Серверы». Выбор общий для группы и переживает перезапуск. Над каждым живым сообщением стоит имя показанного сервера, а в теме 🩺 перечислены все серверы и их состояние.
- **Нагрузка.** Каждый цикл спрашивает у каждого сервера доступность, статусы заданий и заполненность репозиториев. Полное сканирование точек восстановления и выполняющиеся сессии читаются только у выбранного сервера; после переключения первое обновление живых тем может занять до минуты, пока идёт сканирование.
- **Новый сервер** в списке первый цикл только запоминает: уже упавшие на нём задания не присылаются оповещением. То же после переименования сервера — бот узнаёт его заново.

Файл состояния от версии с одним сервером читается как состояние первого сервера в списке, поэтому при переходе ничего не теряется.

## Основные настройки

Полный перечень с комментариями и значениями по умолчанию — в [.env.example](.env.example).

| Переменная | Назначение |
| --- | --- |
| `VEEAM_SERVERS` | Серверы Veeam через запятую: `имя=адрес` или просто адрес (тогда имя — первая часть имени хоста). |
| `VEEAM_BASE_URL` | Прежний способ указать один сервер. Задаётся либо он, либо `VEEAM_SERVERS`. |
| `VEEAM_LEGACY_TLS` | Имена серверов, которым в TLS-рукопожатии предлагаются старые алгоритмы (подписи SHA-1). Нужно старому серверу, который иначе обрывает соединение с `ECONNRESET`. Ослабляет TLS только для названных серверов. |
| `VEEAM_API_VERSION` | Версия заголовка API. Сервер на более старой сборке Veeam отказывает и называет свои версии; с ним бот говорит на новейшей из них и один раз пишет об этом в журнал. |
| `VEEAM_MONITOR_USERNAME`, `VEEAM_MONITOR_PASSWORD` | Данные служебной учётной записи, одной на все серверы. |
| `VEEAM_INSECURE_TLS` | Разрешить сертификат Veeam без доверенной цепочки; по умолчанию `true`. |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_IDS` | Токен бота и начальные чаты для отправки. |
| `TELEGRAM_WEBHOOK_URL`, `TELEGRAM_WEBHOOK_SECRET` | Публичный адрес и секрет webhook; пустой URL включает long polling. |
| `TELEGRAM_ADMIN_KEY` | Ключ для операторских HTTP-маршрутов. |
| `TELEGRAM_MONITOR_INTERVAL_MS` | Интервал проверки Veeam; по умолчанию 60 секунд, `0` отключает периодический опрос. |
| `TELEGRAM_ROUTING_MODE`, `TELEGRAM_ROUTES_FILE` | Режим маршрутизации и необязательный файл правил. |
| `TELEGRAM_LIVE`, `TELEGRAM_LIVE_ORPHANS` | Живые темы и отдельная тема резервных копий без задания. |
| `TELEGRAM_PROTECTION_INTERVAL_MIN` | Интервал полного сканирования точек восстановления; по умолчанию 60 минут (1 час). Первый сбор запускается при старте сервиса. |
| `TELEGRAM_TIMEZONE` | Часовой пояс IANA для времени в сообщениях; пустое значение берёт пояс сервера. |
| `TELEGRAM_DIGEST_HOUR` | Час ежедневной сводки; `-1` отключает её. Команда `/digest` доступна независимо от этого параметра. |
| `TELEGRAM_STATE_FILE`, `LOG_FILE` | Пути к файлу состояния и журналу. |

## HTTP API и диагностика

| Маршрут | Доступ | Назначение |
| --- | --- | --- |
| `GET /api/health` | Открытый | Проверка доступности каждого сервера Veeam: поле `servers`, а `veeam` — первый из них. |
| `GET /api/telegram/status` | Открытый | Состояние интеграции, очереди и монитора. |
| `POST /api/telegram/webhook` | Секрет webhook | Входящие обновления Telegram. |
| `GET /api/telegram/chats` | Ключ администратора | Известные чаты и темы. |
| `GET /api/telegram/routes` | Ключ администратора | Действующие правила и настройки маршрутизации. |
| `POST /api/telegram/routes/reload` | Ключ администратора | Повторно прочитать файл правил. |
| `POST /api/telegram/check` | Ключ администратора | Запустить один цикл проверки. |
| `POST /api/telegram/test` | Ключ администратора | Отправить тестовое событие через маршрутизатор. |
| `POST /api/telegram/notify` | Ключ администратора | Отправить произвольное объявление. |

В операторских запросах передавайте ключ в заголовке `X-Telegram-Admin-Key`. Интерактивное описание схем запросов доступно по `/api/docs`, JSON — по `/api/docs-json` (можно отключить через `API_DOCS=false`). Если оповещения не приходят, проверьте `GET /api/telegram/status`, лог в `logs/backend.log` и количество обнаруженных чатов. Для проверки всего пути доставки используйте `POST /api/telegram/test` с телом, описанным в `/api/docs`.

### Модули и папки

Один Nest-модуль на предмет и одна папка на модуль. Папки лежат слоями, и
любой импорт — и между Nest-модулями, и между файлами — идёт только вниз:

```
updates   TelegramUpdatesModule   команды, кнопки, webhook, HTTP-эндпоинты
monitor   MonitorModule           цикл опроса и алерты; наружу отдаёт только MONITOR
live      LiveModule              live-слоты: что в них написано и одно сообщение на слот
estate    EstateModule            Evidence, карточка задания, сводка, Run'ы
veeam     VeeamModule             HTTP-клиент, токен, модуль чтения, имена репозиториев и прокси
telegram  TelegramModule          доставка: чаты, темы, маршрутизация, файл состояния, язык бота
config                            настройки: одно объявление на переменную
```

Две папки без своего модуля тоже стоят в слоях: `logging` (файловый логгер) — внизу, рядом с `config`; `http` (проба `/api/health` и описание API) — наверху, рядом с `updates`.

`veeam` и `telegram` — соседи одного слоя и друг друга не импортируют. Файл,
который сам ничего из проекта не импортирует (имена слотов, виды уведомлений),
может использовать любой слой.

`test/architecture.test.cjs` падает, если импорт укажет вверх или вбок — между
Nest-модулями или между файлами разных папок, — или если приложение перестанет
собираться.

Файл [docs/veeam-openapi.json](docs/veeam-openapi.json) описывает API самого Veeam; `/api/docs` описывает API этого сервиса.
